AI Coding Week 2

Tags: Technical, Claude

Week Two of testing out Claude code is complete (see week 1 here). Actually, the week ended on Wednesday when my weekly quota ended. That is despite not using it on Saturday at all, and only a little on Sunday. The 7 quota seems to be more like a 3 day quota. I wonder if that is a sales technique?

This (half) week I tried out creating a greenfield project. A simple non-graphical web game that has little commercial prospects, so I don’t care how it goes. Claude just finished a prototype in its allotted time, shaking out a few issues - a worthwhile result.

First I asked it to help out with designing the system. I gave it a couple of paragraphs describing the game and some technical constraints. It then asked long series of very good questions before outputting some design docs and an implementation plan. It mostly understood the brief, and the plan was decent. I was very impressed with this stage, I would happily use Claude again help the design and planning phase of development. The main benefit is that I had Claude log all its decisions and work. Now I have a complete list of ideas, alternatives and the reasons decisions were made - something I’m usually too lazy to bother with (and then regret later).

Then I had Claude work step-by-step (24 steps in the plan) in development. It ran out of quota on the last step (online deployment), but I can run it locally so its not too bad. I looked a little at the code produced, but apart from code duplication and superfluous config, it looked ok. So I mostly let it do its own thing. Often it would find its own mistakes, eventually.

The end result is… decent. Very simple gameplay and a frontend that is “backend developer” quality (so the same as me). It is largely what I asked it to do. I haven’t found any bugs, but do have a long list of improvements and ideas. Thus, I would declare it a successful prototype. Claude produced more than I could have done in 3 days for sure, and probably more than I could do in a solid week’s work. Although there are a few things I would have improved along the way, so I like to think my quality would be higher.

There are two big issues I see:

  • Quota limits: At first I thought this week it was getting more done considering the quota used. However, it just seems to be small projects (such as the initial greenfield work) result in a smaller context, and thus lower quota usage. I’m not sure what the solution is. Maybe break projects into smaller components. Maybe avoid long running sessions (don’t do more than a couple of compactions). Some experimentation is required.
  • It also makes me want to let it free reign - or as Claude calls it, YOLO mode! Although I’m way to scared and careful with my data to allow it. I’ll try looking at isolated environments like Claude Code Web or Sprites.io to see if they work well enough.

Next week I’ll try getting Claude to create something in Godot (maybe a client for this week’s game). If it can do that then I can see this being useful, despite the limitations.

AI Coding Week 1

Tags: Technical, Claude

In the last couple of months I have been hearing increasingly positive reviews on LLM coding assistants. I gave the LLM’s a quick try almost a year ago (for free) and was not particularly impressed. However, the buzz now is they have massively improved and that the business of coding has changed. Being curious, I signed up for a month of Claude Code Pro to see if this view has any merit. I’ll aim to write up my thoughts at the end of each week - this is week 1.

I should begin by saying this post is not written by LLM in any way. Nor are any of the posts in this blog (so far at least).

Before starting I read many posts with advice about how to get the most of AI assistants (for examples, see here, here and here). They often talk about the benefits of planning and constraining LLMs with testing harnesses and linting tools to guide its work. Thus I decided to start by reviewing an existing Scala project containing a library of code useful in many of my game projects. It had >75% test coverage and linters already setup, plus a compiler option set to break the build on warnings (not just errors). So I set Claude to work reviewing the code, fixing bugs and suggesting improvements.

My impression was “damn, this really works.” It has fixed around 30 issues or improvements it found in the code. Most were minor, but a couple were embarrassing bugs. There were also 2 false positives - things it said were bugs initially, but on further investigation (by Claude) turned out not to be bugs. I also set it to improve test coverage, and it did so sensibly to over 85%. I reviewed closely every line added, removed or updated. Most of the fixes were small and were committed unchanged, a couple of the larger ones needed some changes to better match my (functional) style.

Overall, based on my experience in the industry, Claude acted like a good and attentive junior developer. It went through and diligently found bugs, long after my eyes would have glazed over. I had a comment “// TODO: nasty hack” and it found a 1 line fix (replacing my 3 lines) in a part of the Standard Scala library I didn’t know about - that impressed me. At first it would miss some things, or have trouble working out parts of the project (like the coverage system). However, after updating its config it worked much better. The main reason I describe it as junior is because it largely offered no pushback or initiative. It always agreed with me and told me I was right (unlikely :). It did exactly what I asked and only that. Probably this is by design, and maybe because it was working in an existing project. It also had a tendency to produce procedural code, which doesn’t fit a functional language like Scala. Still it definitely provided value and at a cost orders of magnitude below an actual junior dev.

Still for a small independent dev like me, cost is the main issue with Claude. Or at least, the amount of usage for the cost. Claude gives a 5-hour and 7 day quota. I regularly hit my 5-hour quota after a hour, and always before the 2 hour mark. My 7-day quota was reached over a day before the deadline. This is despite trying a few tricks to keep the usage low, like downgrading the effort in config. I also add a status line giving continuous notice of usage and what the cost would be if I allowed Claude to exceed its quota. I’m very happy going over quota is off by default - the non-plan costs rise fast and quickly exceed any reasonable budget I would allow. I will have to watch this closely, otherwise it will severely restrict what is possible.

Overall I am impressed. It’s not perfect, but definitely useful. It has made me think about my design philosophy, rather than being completely focussed on implementation details. Next week, when my quota resets, I’ll give it a greenfield project and see how it handles that.

Boardgames of 2025

Tags: Games, Board Games

Last year I played less boardgames than 2024. Mostly this is due to not playing online and just being busy with other things (travel, etc) so missing game days. I expect to play more this year. I have started playing with a couple of groups more regularly. The 6 train games on the list were played at the 18XX group. For more information on why these games are worth playing checkout this post. The miniature wargames played this year (Strength & Honour and Armada) are with a friend from the local strategy boardgame group who turned out to live nearby and enjoy such games (a lucky find!).

Here are my thoughts on some games I played multiple times this year, and haven’t previously reviewed:

  • Splendor Duel: A two-player version of the popular Splendor. Collect gems to create jewellery and thus your fortune. Not sure I’m qualified to discuss this one due to a very low win ratio. I must be missing something which suggests a relatively and surprisingly deep game for the simple mechanics. Still a fun quick game, will play again.
  • Strength & Honour: A 2mm scale ancients miniatures wargame, although we played successfully with just pieces of cardboard. Victories are won by forcing your enemy to break, but sometimes you just can’t get your units to act. Initial placement of units and maintaining a supporting line are vital. Very interesting and will play more as we are going through linked scenarios designed by my opponent.
  • Star Wars Armada: Amazingly pretty miniatures wargame of Star Wars capital ship battles. The fighting seems to be based on naval battles with large slow moving ships pummeling each other while small squadrons nibble around the edges. Satisfying game that seems mostly decided by the meta-game.
  • Undaunted: Normandy: Extremely clever deckbuilder of WWII squad level combat. The cards in hand represent your ability to order squads to acts. You then play cards to move across a map created from various combinations of terrain tiles. The mechanics and theme fit very well. Hopefully will get to play this much more over the coming year.
  • Molly House: I played this at the Strategy Boardgames group and it took two plays to understand what was going on - I’d happily play a third. Feels like a very tactical game (well laid plans go astray quickly) of “coopertition” - you have to both cooperate and compete with the fellow players. Like a mix of Churchill and a slightly less complex Pax Pamir. All this in a game about throwing gay parties and dodging police in 18th century London. Amazing.
  • Agamemnon: Supposedly a short game about the Trojan war, but is really an abstract area control game with the thinnest of themes applied over the top. Entertaining but forgettable.
  • Hissy Fit: A 5-minute party card game about getting a rowdy cat to the vet. Quick, easy and fun, but no need to play again.

Goals 2026

Tags: Goals

So how did I go with last year’s goals?

  • Return to a decent level of fitness and strength: Partial success. I have started indoor cycling and my aerobic fitness is improving. However, I have barely gone to the gym at all this year.
  • Improve Spanish: Achieved, at least as far as practicing almost every day. I think I am better, but can’t be certain.
  • Start Ci2D: Started, but barely. So far it’s just a proof that Godot can meet my needs.
  • Modelling for 3D printing: Nope, nothing. Also seems less important now. I have too many unprinted models and a large grey pile of shame. There is no need to create more.
  • Read books: Achieved. The goal was met with a fortnight to go, and I made it explicitly because there was a target to reach. I have read some good books this year, and a couple that were not for me, but enjoyed the process of reading all of them. I will definitely try this again.

For the coming year I’ve decided to be more specific and less ambitious in my goals (following the success of last year’s Read books goal). I don’t want achieving a goal to be a struggle, and I want measurable results. They should be a starting point for a better life. The more aspirational or vague things I would like to do are now in a separate list. I won’t feel bad if I don’t even start them.

Goals:

  • Read 12 books: Worked well last year, let’s try it again.
  • Read social media less than 10 minutes/day on 300+ days: I have found myself spending increasing amounts of time on various sorts of social media. I would set this to 0, but unfortunately some groups and people are only contactable through these platforms. So 10 minutes should be more than enough to discover/organise with them. This limit also includes YouTube shorts/clips. It does not include news, but not sure what to do with the overlap (as much of modern news output is dross). I’ll have to work that out. I already had 2 days this year (out of 5!) where I exceeded this limit, so will have to improve.
  • 105 exercise sessions: At this time the main thing is just to keep exercising regularly. This is 2 sessions/week, enough to keep momentum. A bit more and there should be improvement.
  • Practice Spanish for 10+ minutes/day: About what I already do. As part of this I should try moving away from Duolingo, I am find the gains there slowing. I need to practice listening and grammar drills more than that site allows (on their free program).

Aspirations:

  • Sit Less: At the start of last year my desk chair broke and I replaced it with an ergonomic office chair. It works, too well! Now I sit a lot more and for longer. There is a correlation between sitting for extended periods and my back aching or legs being stiff. I should make better use of my sit/stand desk, and limit sitting to 30 minutes or so at a time.
  • Learn Python; try AI coding; general programming: Just code for fun.
  • Paint gray pile of shame: Painting minis takes much longer than I expected. It is very easy to print faster than I can paint, and so now I have 10+ Armada, 10+ X-wing, and nearly 100 Battletech minis waiting for paint, plus lots of tokens and terrain. I should work through it as much as possible (not all of it, realistically there is more than a year’s worth there).
  • CI2D demo: Rather than create full games, I will now aim to create demos, and see later which ones are worth pursuing.
  • Catch up on old blog threads: There are a bunch of notes for blog posts yet to be written. I haven’t written about my time in KL or Valencia. My work history series stops in 2005. These should be continued before the memory fades (if that hasn’t happened already).
  • Start learning Mandarin: I started learning Mandarin this year for a few weeks on Duolingo, but then they changed the way the site worked so that it became unreasonably hard to do more than one course. So Mandarin was given up in favour of continuing Spanish.
  • Play 5 boardgames at least 5 times: Almost made this in 2024 without trying. With a bit of attention it should be easy and fun. Online plays count.
